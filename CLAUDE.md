## 1. ARCHITECTURE & STATE
- **Layers (Import downward only):** `config` → `core` → `display` → `storage` → `services` → `ui` → `cli`.
- **Colors:** Managed strictly in `apex.display.colors`. Use `red` (kills), `green` (wins), `orange` (levels: `\033[38;5;208m`); `cyan` / `purple` (`\033[38;5;93m`) / `blue` only for category tags, everywhere (menu, `help`, undo, `TOTALS`): `[ACCOUNT...]` purple, `[MATCH]` cyan, `[BASE...]` blue. Never import `COLOR` boolean directly. Data files must remain uncolored. Use comma separators (`1,500`) in UI, plain digits in data files.
- **Data Files:** Commands read and write both data files only through `Ledger` (`storage/ledger.py`): each file read at most once, one all-or-nothing commit (month file first) when its `with` block ends. Atomic writes via `storage/atomic.py`. Read current month once. `account_stats.txt` holds `@ACCOUNT` and `@BASE`. Monthly headers carry earlier months forward: `@HIST`, `@PREV`, `@HL`, `@PL`, `@LV`, `@LL` (last match per legend), `@TK` (Top 5 matches); `@BU` = undo records (`Change`). A monthly line that cannot be read is skipped with a stderr warning (`read_month`) and kept in the file as `@BAD`, so a later save does not lose it. Records are typed in `core/records.py` (`Tally`, `Stored`, `TopMatch`, `LevelDay`, `Periods`, `LegendRow`, `MatchTotals`, `Entry`, `Change`, `Month`): use named fields, never positional indexes.
- **Log Record:** `L | DATE | LEGEND | KILLS | WINS | LEVEL | ID | ACC | SRC`. `ACC=1` = added to the account totals (NOT "from `account`"). `SRC` = origin: `M` match/quick, `A` account gain, `B` base gain, `L` level update (`record_gain(source=...)` for `M`/`A`/`B`, `record_level` for `L`). Files without `SRC` still load: level-only = `L`, the rest = `M`.
- **REPL State:** Exits only on empty Enter (no `q`). No `logs` command (`log` exists). Sticky legend (REPL only) is OFF by default; `p <name>` locks a legend set with `base` (missing/unknown name: error, nothing changes). The locked legend applies to matches without a legend AND to `<n>k` / `<n>w` without one (`save_quick(..., legend)`); a legend typed in an entry is used as is and leaves the lock unchanged. A typed `-` legend, or `-` alone on a line (saves nothing), unpins it and turns it OFF. Level entries (`<n>l`, `accountl <n>`) never take a legend.

## 2. COMMAND LOGIC
- **Input Order:** matches are `<kills>`, `<kills> <wins> [legend]` or `<kills> <legend>` (`parse_match`). Kills always first. A number alone = kills, wins 0; `<kills> <legend>` (1 number, then a legend) = wins 1; two numbers are always kills and wins (no win added). Matches take NO level (`parse_legend` rejects any number after kills/wins); levels come only from `<n>l` / `accountl <n>`.
- **Shared Totals Decision:** `account` and `base` both classify typed totals with `decide_totals` (`core/totals.py`): `FIRST`, `LOWERED`, `UNCHANGED` or `GAINED`.
- **Downgrade Protection:** `account`, `base` (`0 0` removal included; both through `decide_totals`) and `accountl` call `confirm()` (`confirm_lower`, REPL/CLI) before lowering a value below the current one: prompt `Warning: New value is lower than current. Proceed? (y/n):`; only `y` proceeds, anything else raises `ValueError(ABORTED)` and changes nothing.
- **Account (`account <k> <w> [lvl]`):** No legend, no `--l`, no sticky legend. Sets global totals; `lvl` also records the account level (a level entry saved first; equal level logs nothing). One confirmation covers the whole command, asked if the level or the totals would go down. If totals exist, logs diff as an entry with no legend (`SRC=A`). Lower values need a confirmation; once confirmed they replace the totals, with a `@BU` undo record and nothing logged. Every `ACCOUNT` line shows the current level (`account_line(..., level=)`, `level_txt`: word and number orange).
- **Base (`base <legend> <k> <w>`):** Legend, kills and wins only. Sets legend all-time totals. A gain (typed > current all-time totals) is logged through `record_gain` as an `L` entry for that legend (`SRC=B`): it shows in `report` and bumps `@ACCOUNT` (like `account`); undo removes it. A first set, a correction (lower values) or a removal (`0 0`) logs NO entry (only an `@BU` undo record, `Ledger.change_base` / `Ledger.remove_base`). A stored base of `0 0` is valid (logged entries cover the totals); only a typed `0 0` removes. Discard input if lower than already logged values. `SRC=B` entries are never single matches: excluded from `log`, the Top 5 (`@TK`) and `LAST MATCH` (`@LL`).
- **Quick (`<n>k [legend]` / `<n>w [legend]`):** `parse_quick`. A legend typed after them is used as is, bypassing the sticky legend (which stays pinned/unchanged); without one they take the pinned legend, if any.
- **Top 5 Matches:** all-time leaderboard of single matches by kills (`top_matches`, `TOP_MATCHES = 5`): `SRC=M` entries with kills > 0 (quick `<n>k` included; account/base gains never), ties = earlier first. Derived from the carried `@TK` rows + the current file, so undo needs no extra step; `roll_over` stores the new top 5 in `@TK`. Shown by `m`.
- **Levels (`<n>l` or `accountl <n>`):** `<n>l` is relative (`save_quick`), `accountl <n>` is absolute (`accountl_cmd`); all are saved by `record_level`, whose callers confirm any lowering first. A level decreases only through a confirmed `accountl`, so the current level is the most recently recorded one (`latest_level`), not the highest.
- **SAVED line:** matches (and quick `<n>k`/`<n>w`, account and base gains) show the current account level (latest recorded, `Saved.level`) via `fmt_saved(rec, level)`; `LEVEL -` if none. Order follows input: `SAVED  <legend>  KILLS <k>  WINS <w>  LEVEL <n>  (<date>)`.
- **Undo:** LIFO by `ID`. Reverts `L` (match), `@BU` (base change) and account changes. Account changes are `@BU` lines with legend `@ACCOUNT` (`ACC_TAG`) holding the previous `@ACCOUNT` (k, w, updated; `-` = never set): the first save or a confirmed lowering writes one (`Ledger.change_account`), an account gain writes one with the SAME `ID` as its `SRC=A` entry (`Ledger.add`); undo removes both together and restores the old totals exactly (`Ledger.revert_last`). Old `SRC=A` entries without a snapshot fall back to subtracting the gain. If `base` is undone, correctly reverts base stats without data corruption. After every undo, prints `PREVIOUS LOG:` with the remaining action of highest `ID` (`Month.last_action()`, what the next undo reverts; `fmt_previous`), labeled `[MATCH]` (cyan), `[ACCOUNT UPDATE]` (purple: `SRC=A` entry or account `@BU`), `[BASE UPDATE]` (blue: `SRC=B` entry or base `@BU`) or `[LEVEL UPDATE]` (orange); `none` if nothing is left. In it the whole `KILLS <n>` is red and the whole `WINS <n>` green (`kw_values`), e.g. `Legend: Rampart | KILLS +8 | WINS +0`.

## 3. REPORTING & UI LAYOUT
- **Help:** `help` prints a dedicated screen (`help_text`) explaining each command; it does not reprint the main menu.
- **Main Menu (`quick_guide`):** shown at REPL start and on unrecognized input. Strict layout order (`help` too): `[ ACCOUNT ]`, `[ BASE ]`, `[ MATCH ]`, `[ STICKY ]`, `[ TABLES ]`, `[ SYSTEM ]`.
- **`log`:** two side-by-side tables within 79 columns, `LOG_RECENT` (20) rows each, oldest first. Left: current file's `SRC=M` entries only (account/base gains and level updates excluded). Right: carried `@LV` days + current-file entries with a level, with the change from the previous level. Reads only the current file.
- **Menu Colors:** kills red, wins green, levels orange (`[lvl]`, `<lvl>`, `<n>l`), every command `steel` (soft blue), title `yellow`, explanations and the other `[ TAG ]`s `gray`; borders and `<name>` / `<legend>` default.
- **`report`:** Two side-by-side tables over the same `WINDOWS` (7, 30, 90, 180 and 365 days): left `# SUMMARY` (`period_summary`: `PERIOD | FROM | KILLS | WINS`, one row per window + `ALL-TIME`), right `LEVELS GAINED` (`levels_gained`, one row per window + `ALL-TIME`: current level minus the first level ever recorded, `first_level`; 0 if none). Windows count entries after `FROM` up to today; the older monthly files are read too (`older_logs`). There is no `lv` command. Rows are 87 columns; the title line runs longer (about 110).
- **`m`:** Current month kills/wins, then `TOP 5 ALL-TIME HIGHEST KILL MATCHES` (`top_matches`): `SRC=M` entries with kills > 0, ties = earlier first. Carried across months in the `@TK` header (top 5 of previous months).
- **`l` (Legends):** 2-columns (Side-by-side). Left: Legends initialized via `base`, sorted by all-time KILLS descending, with the date and time (YYYY-MM-DD HH:MM) of each one's last logged match (`LAST MATCH`, `-` if none; `SRC=M` entries only, carried across months in the `@LL` header) (NO grand totals). Variants (one word, no space; `legend_text(d, sort, search)`, `L_SORTS`): `l` = by kills, `lw` = by wins, `la` = by name, `lm` = by last match (most recent first, never played at the bottom), `ls <name>` = left column filtered by name (case-insensitive substring, by kills). No `lk` (`l` is already by kills); the old `l a` / `l w` / `l s` forms no longer exist. Right: "TOP 3 THIS MONTH" by kills (never filtered).
- **`k` / `w`:** List real legends only. Show month, semiannual, annual, all-time. Ends with `GRAND TOTAL` row.
- **Levels UI:** Apply ANSI Orange ONLY to specific level variables/outputs (e.g., the 3rd column "GAINED" header word and values, current level number, and error numbers).
